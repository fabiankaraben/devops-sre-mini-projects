How It Works: Core Architecture & SRE Concepts

Key networking and traffic routing principles implemented in this project.

1. Reverse Proxy vs. Direct Access

Clients connect exclusively to Nginx on port 8080 (or 80). Nginx terminates the connection, handles buffering, rate limits, and routes /api/* traffic to the internal backend on port 8000 without exposing it directly to the public internet.

2. Gzip Dynamic Compression

The proxy inspects the client's Accept-Encoding: gzip header. If present and payload size exceeds gzip_min_length 256, Nginx compresses the response using level 6 compression, reducing network transfer size by up to 70%.

3. Aggressive Asset Caching

Static assets (CSS, JS, images) receive Cache-Control: public, max-age=31536000, immutable. Browsers store these locally for 1 year, eliminating redundant requests. HTML files use no-cache so users receive updates instantly.

4. Header Preservation (X-Forwarded-*)

Because Nginx acts as an intermediary, backend logs would see 127.0.0.1 as the client IP. Directives like proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; preserve the real client IP for authentication and audit logs.
